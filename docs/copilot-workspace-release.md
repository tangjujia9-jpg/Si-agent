## 运行链路修复

本轮发现工具队列和 assistant 历史共用同一个列表。执行工具时消费队列，会连带清空已经记录的 tool_calls。
真实模型随后拿不到完整的工具调用/结果对应关系，重复读取文件并最终触发预算限制。
现在队列使用独立的 JSON 副本，历史保持完整。新增测试在修复前以空 tool_calls 失败，修复后通过。

文件工具还会限制序列化结果大小，列表返回 next_offset，读取返回 next_line，避免大结果被通用执行器整块替换后反复重读。
流式模型输出按小批量持久化；发布文字后不自动重试，中断不能成为成功回答。忘记来源时，关联 llm_delta 事件也会脱敏。

## 数据迁移

迁移从 Copilot SQLite 开始，原数据库、迁移前备份和上游 `.waku/` 保持保留。
迁移前存在 6 个项目、11 段会话、17 条消息、7 次运行、70 个上下文节点和 153 条层级索引。
同时迁入 31 条证据、30 个版本、12 个记忆写入记录、12 个候选、64 个任务、5 个工具操作和 2 条遗忘屏障。
迁移校验逐项比较原字段，并检查向量浮点精度和自引用关系；PostgreSQL 全文表示从原文重建。

`scripts/migrate_copilot_sqlite.py` 只读打开源库，拒绝非空目标，并在同一目标事务内复制与校验。
新增迁移测试覆盖旧表缺少新增项目列、向量、自引用和拒绝二次覆盖。
本机 Docker Desktop 不可用，因此本机 PostgreSQL 使用已有 WSL Ubuntu 安装运行；Compose 的验证由 GitHub CI 执行。

## 实测

真实 hy3 在本地项目中调用两次 read_project_file 后完成回答；该次运行包含 2 轮模型调用、45 批持久化文字输出。
客户端在运行完成前收到了文字，两个文件操作均成功，整次端到端检查约 28.37 秒。
这个样本证明实际链路可用，不代表稳定吞吐量或任务成功率基准。

联调还记录了原 SSH 隧道断开导致的连接失败，以及修复前工具历史丢失导致的预算失败；没有删除这些运行记录。
当前 18790 隧道已恢复，Jev 继续禁用。

浏览器验收使用独立 PostgreSQL schema 与离线模型，覆盖文件夹快照、敏感文件过滤、导入、建议确认、事实修正、版本、引用、刷新恢复、独立监控、忘记和手机宽度检查。
真实模型页面另做了桌面、监控与手机截图检查。
后端回归包含真实 PostgreSQL 与独立 SQLite；历史迁移夹具改用当时的 SQL 表结构，避免旧版本夹具调用当前 ORM。

## 能力边界与下一步

当前产品提供单用户本地项目知识与开发辅助，没有登录、多租户权限、shell、写文件、PDF/Word 解析或自动 Git 修改。
本地关联可读取实时文件，浏览器导入只保留快照；向量与摘要只有导入后才建立。
监控统计覆盖最近 100 条记录，模型未报告用量时不能据此推算账单；没有模型价格数据时不显示虚构成本。
历史旧 span 保留原计时精度，新 span 使用 perf_counter 并保留三位毫秒。

Langfuse 真实服务部署、trace 跳转、PostgreSQL 质量基线、人工样本复核和 Eval Lab 按[后续计划](copilot-roadmap.md)继续推进。
当前自有监控页面不冒充已完成 Langfuse 实例联调。
启动命令见[后端手册](copilot-backend.md)，界面说明见[工作台手册](copilot-console.zh-CN.md)。
