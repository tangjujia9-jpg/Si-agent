# Si-agent 长任务上下文接续验收

日期：2026-10-22。本轮实现长任务方案的 A 阶段：语义压缩、预算结算、持久化工具结果回读和中文观测入口。开发工具闭环仍属于 B 阶段。

## 上下文现在如何组成

| 部分 | 内容与权威来源 | 压缩时如何处理 |
|---|---|---|
| 系统规则 | 固定角色、工具边界、引用及审批规则 | 始终保留，不让资料或摘要进入系统指令 |
| 当前请求与执行状态 | 用户完整请求；数据库记录的操作 ID、真实状态、资源 ID、错误码、待执行调用和工具计数 | 当前请求保留原文；操作状态由执行器读取，摘要不能替它宣告成功 |
| 工作摘要 | 目标、原始约束、决策、过程、未决问题和下一步 | 只覆盖较早的完整交互；原始约束须带消息 ID 和可核验的原句 |
| 最近交互 | 尚未被摘要覆盖的 user/assistant 消息和完整工具交换 | 工具调用与结果成组保留，不能把并行工具批次切开 |
| 检索证据 | 当前项目有效的 Si Memory 命中、引用和版本 | 继续独立编译；同一 Run 复用初次检索，显式搜索工具仍可补查 |

摘要、状态和证据以 `REFERENCE_CONTEXT` 数据块进入模型请求，不提升为系统指令。消息 ID 和操作 ID 是原文定位，不能拼成 `si://` 引用；正式引用必须来自实际来源 URI。
模型摘要中的过程描述仍可能失真。产品把它展示为派生工作记录，工具是否成功、是否批准则以执行器记录为准。
首版摘要正文上限为 12,000 UTF-8 字节，原句约束最多 32 条；超过限制会停止并保留原文，不会悄悄删除较早约束。

```text
用户消息 / 完整工具批次完成
  → 校验原始消息、来源版本、遗忘及摘要依赖
  → 读取执行器状态，复用或补充检索证据
  → 计算单次输入、输出预留与协议余量
  → 接近阈值：对较早的完整交互生成增量摘要
  → 校验 JSON、约束原句、覆盖边界和来源版本
  → 原子提交摘要与 Run 检查点
  → 再核对窗口、累计预算及截止时间
  → 流式模型调用 → 工具 / 审批暂停 / 回答
```

## 压缩与持久化

旧正常路径只加载最近 12 条消息。现在新 Run 加载最近有效摘要，以及覆盖序号之后的有效原始消息。模型请求变短后，数据库中的原文继续保留。
跨回合继承摘要；同一 ReAct Run 在下一次模型调用前也检查容量，不在每次工具调用后立即付费生成摘要。

设窗口为 C、输出上限为 O、协议余量为 M，可用输入为 E=C−O−M。当前在输入估算超过 E 的 70% 时尝试压缩，以 E 的 50% 为目标；最近交互目标不超过 16K。
这些目标服从完整工具批次和必要内容边界，实际结果可能高于 50%。过短的历史前缀不值得生成摘要时，仍在窗口内就保留原文。

摘要调用只输入上一次有效摘要与新覆盖的前缀，关闭业务工具。超长历史按安全边界分批处理，摘要请求自身也要装进模型窗口。
每批最多尝试两次，继承原截止时间并计入预算。非法 JSON、伪造约束原句、摘要不缩短、来源变化均不能提交；失败时保留原始记录，不通过静默删除历史继续。
单个不可分割请求或最新工具交换超过窗口时，系统明确停止，不能承诺任意输入都可无损压缩。

迁移 `0009_context_summaries` 新增摘要表，保存项目、会话、Run、输入哈希、覆盖边界、策略版本、模型、结构化正文、来源依赖和用量。
摘要不是正式长期记忆，不直接写入候选或虚拟记忆目录。原有异步长期记忆蒸馏继续处理原始用户消息。
普通来源修正会让旧摘要失效；后续 Run 从仍有效的原文重新组织上下文。忘记来源会脱敏关联摘要、历史和工具结果，取消受影响的进行中任务。
摘要生成期间发生遗忘时，提交前再次检查租约、消息哈希和来源版本，防止把刚删除的内容写回来。

## 工具原文可以回读

本轮新增 `read_operation_result(operation_id, offset, limit)`，项目执行器共 9 个工具。
现有记忆、文件工具继续工作；新增工具按操作 ID 分页读取数据库中保留的完整结果，不能提交任意磁盘路径，也不能跨项目读取。

工具结果超过 6,000 UTF-8 字节时，模型收到状态、操作 ID、资源定位和预览，完整正文保存在 `tool_operations.result`。
首次执行、审批后的恢复和重放已有结果使用相同投影。成功操作仍保持 succeeded，不把“正文未全部发送”误写为业务 partial。
回读页同时限制字符和 UTF-8 字节，避免中文日志再次被缩成无法继续读取的预览；后续使用返回的 next_offset 续读。
忘记或来源版本失效后，旧操作的正文也不能绕过校验回读。

当前结果正文全部保存在 PostgreSQL。文件系统大对象存储、补丁、命令执行、Git 差异和测试构建工具尚未在本轮交付。

## 三种 token 限制分别生效

| 限制 | 当前入口 | 意义 |
|---|---|---|
| 单次窗口 | Provider 的 CONTEXT_WINDOW；本机 hy3 为 65,536 | 本次输入、输出预留和协议余量必须装进去 |
| 单次输出 | API max_output_tokens，256–4,096，默认 2,048；工作台默认 4K，可切换 2K | 限制一次生成，部分模型还在该额度内消耗推理 token |
| 累计任务预算 | API max_tokens，默认 64,000、最高 256,000；工作台仍为 64,000 | 约束同一 Run 的摘要、模型重试和多轮消耗 |

输入仍按 JSON UTF-8 字节上界估算，不能把它当作实际 token 或账单。
每次调用先持久化带唯一 ID 的预留，收到有效 usage 后只结算一次，释放估算与报告之间的差额；实际报告更大时相应增加累计消耗。
网络失败、进程中断、零值或不完整报告继续保留预留，并标记为未结算。重启不能假设这些调用免费。
Embedding 与可选 Jev 目前仍按保守预留计入，未实现真实用量结算；本轮没有启用 Jev。
接口报告不是核验后的账单。成本展示不能用估算 token 冒充厂商计费。

上游拒绝长度时，只有尚未发布文字才允许减半有效窗口，并尝试语义压缩后重试一次。工具不重放，预算与截止时间不放宽。
已经发出的文字或不完整模型流不会被自动重试并冒充完成；输出耗尽仍报告未完成。

## 前端与运行

项目对话显示“正在整理上下文”，完成后继续生成或执行工具。输入框下方可以选择单次输出 2K / 4K，并记住本机偏好；不把它混称为上下文窗口。
项目监控中的运行详情增加“工作上下文与原文定位”，展开后按需读取摘要、约束原句、执行器状态和依赖定位。
预算区域区分接口报告 token、未结算预留和计入累计预算的数值；原始事件包含 compaction_start/end/failed、summary_call 和 usage_settled。
摘要模型调用生成独立 summarization span，可沿用已有的可选 Langfuse 导出；真实 Langfuse 实例联调仍在后续计划中。

本机入口为工作台 `http://127.0.0.1:5186/`、项目监控 `/monitor`、API `http://127.0.0.1:8016/docs`。
运行 API、Worker、Web 和模型 SSH 隧道的命令见[后端手册](copilot-backend.md)。旧 SQLite 和现有项目资料保留。
PostgreSQL 本轮先保存迁移前备份，再升级到 0009。

## 验证记录

确定性测试覆盖长会话、跨 Run 接续、并行工具边界、原句校验、预算结算、审批后恢复、大结果中文分页、来源修正、遗忘及摘要期间遗忘。
新增用例曾在缺少消息依赖、恢复路径直接返回完整大结果和上下文检查接口混用消息结构时失败；修复后分别验证。

真实验收使用已有 workbuddy2api 的 hy3，以及隔离 PostgreSQL schema 中的 24 条合成历史。测试不使用真实项目资料，不调用 Embedding，也不启用 Jev。
首次以 2,048 输出额度运行时，摘要成功，但业务回答耗尽输出额度，系统报告 incomplete_model_response。这个失败保留在本地验收记录中。
改用 4,096 后，压缩与后续回答完成；另一个 Run 也成功继承摘要，复述数据库和语言约束。
结果只验证这组合成样本，不证明摘要无损、模型最大窗口或普遍任务成功率。引用准确性与复杂语义质量仍需固定数据集评估。

完整测试计数、真实调用最终记录和 CI 结果随本轮发布填写。
