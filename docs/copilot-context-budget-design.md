# Si-agent 上下文预算与独立记忆服务设计

本轮先修复多轮任务的上下文增长，再把独立记忆接入作为下一轮交付目标。
Si-agent 的产品主体是 Agent；Si Memory 通过相同的服务契约为它及外部 Agent 提供记忆。

## 已核实的问题

当前本机检索门使用 LocalDecisions。规则只跳过 hi、hello、你好、谢谢、thanks，
其他输入保守检索；Jev 未启用。小于 1 ms 衡量的是本地规则，不包含 Embedding。
首次检索结果缓存在 Run 内；工具迭代复用结果，显式 search_memory 可以补查。

本机两条 context_budget 失败发生于运行时检查。旧实现把单次模型窗口不足与累计运行预算不足
混成同一个错误，同时使用 UTF-8 字节上界估算输入。32,768 是应用配置，不能据此声称
hy3 的实际窗口只有 32K；网关 /v1/models 未提供该模型的窗口值。

## 请求收缩规则

每轮请求分别核对模型窗口和累计运行预算，预留输出及协议余量。估算仍使用保守字节上界，
真实 usage 单独记录，不把估算显示为收费 token。历史、工具 schema、证据、当前输入均计入。

超过预算时，按以下顺序修改将发给 Provider 的副本：

1. 按完整用户回合移除最早的历史，保留当前用户请求。
2. 将当前 Loop 较早的工具正文替换为明确的省略标记和资源定位信息，保留最近一组工具结果。
3. 缩短较早工具调用时的 assistant 正文，保留调用 ID、名称及参数。
4. 通过 Context Compiler 减少检索证据预算，保留完整引用标头。
5. 最小请求仍超限时明确停止，区分 context_budget 与 token_budget。

原始消息、工具结果、数据库检查点和审批记录不因请求收缩而删除。
assistant tool_calls 与 tool_call_id 成对保留，不把工具输出截断成无效协议。
省略内容不是语义摘要，也不是新的长期事实。模型需要原文时通过只读工具重新获取。
调用前继续校验来源有效性；忘记和来源失效检查优先于缓存与收缩。

上游明确拒绝上下文长度时，只有尚未输出任何文字才允许把本次有效窗口减半并重试一次。
第二次仍失败就报告 provider_context_length。其他 400 错误不按长度错误重试。
恢复不重放工具，不增加原有截止时间或累计预算，也不记录上游异常原文。
事件记录策略来源、输入估算、窗口、剩余预算、收缩计数及恢复次数，不保存 prompt。

## 下一轮：Si Memory 独立接入

目标边界为 `Agent Runtime → Memory Service ← MCP / HTTP`。MCP 适配层复用记忆服务，
不导入 Agent Loop，不触发聊天模型，不另建一套目录、冲突或遗忘存储。
现有 REST 支持按项目检索、证据、版本及候选操作；外部 MCP server 尚未交付。

首版采用可选依赖的 stdio MCP，进程配置绑定 user/project 和只读或可提议权限。
工具参数不能覆盖进程身份或跨项目。远程 HTTP MCP 在具备鉴权与令牌作用域后再开放。

| 接口 | 目标行为 |
|---|---|
| search / read / list | 返回 si:// 引用、版本和证据，按需展开层级 |
| propose | 外部 Agent 提交有来源的候选，不能直接写成正式事实 |
| candidate_status | 查询审批、冲突、应用结果，支持幂等重试 |
| forget_preview / forget | 显示影响；危险动作走可信人工确认，不能由模型自签批准 |

验收需由外部 MCP 客户端完成检索和读证据，再由 Si-agent 对话使用同一条记忆；
确认跨会话修正、项目隔离、幂等及遗忘屏障。仅通过协议握手不算完成。
首版不对公网暴露无鉴权的现有单用户 API。

之后依次补 PostgreSQL 质量基线与 Eval Lab、真实 Langfuse 实例联调，再扩展外部记忆后端。
检索门先保持可解释规则，Jev 的默认启用依赖中文样本评测，不能用单个演示问题决定。
