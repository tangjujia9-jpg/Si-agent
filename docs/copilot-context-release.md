## 已核实的运行行为

本机 `SI_DECISION_BACKEND=local`，Jev 未启用。当前本地规则只跳过少数完整问候语，
其他输入保守召回；门判断小于 1 ms 不代表检索没有 Embedding。
同一 Run 的初始检索缓存复用于工具迭代，模型可通过 search_memory 显式补查。
事件现在记录 local-rule / 是否检索 / 原因，前端执行过程展示策略来源。

已有失败记录包含两条 context_budget 与一条 APIConnectionError。
两条预算失败发生在本地输入检查，不是上游模型返回的长度错误；其中一次任务的累计上限仅 24,000。
旧错误码没有区分累计预算与单次窗口，现在分别报告 token_budget 与 context_budget。
本机 hy3 配置窗口为 32,768；通过已授权接口查询 /v1/models 未得到实际窗口或输出上限。
本轮没有用大输入压测上游；新增回归使用离线模型与演示向量。

## 实现

- 每次请求为输出与协议预留预算，同时检查模型窗口和本次任务剩余额度。
- 收缩只作用于请求副本，按完整回合移除旧历史、省略较早工具正文和叙述，再减少检索证据。
- 当前问题、最新一组工具交换、工具 schema、系统指令和调用对应关系保持完整。
- 原始消息、工具结果、审批和检查点保持保留；省略标记不伪装成事实摘要。
- 上游明确返回长度拒绝且尚未发布文字时，缩小有效窗口，最多恢复一次；请求没有变小就停止。
- 恢复不重放工具、不放宽累计预算，也不记录上游可能含密钥或 prompt 的异常原文。
- context_plan / context_recovery 事件记录估算与收缩；监控页提供预算详情。

预算仍使用 UTF-8 字节上界保守预留，模型真实用量单独统计。任务足够长时仍会达到预算、
工具数、迭代或截止时间限制；这轮不把无限执行当作可靠性优化。
具体工具共 8 个，“记忆建议”默认开启；关闭后只暴露五个只读工具。
完整清单见[运行时手册](copilot-runtime.md)。
