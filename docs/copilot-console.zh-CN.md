# Si-agent 前端使用说明

Si-agent 工作台提供项目对话、上下文浏览和记忆审核三个主页面。点击目录节点或回答中的引用后，
页面下方会展开记忆检查器；项目对话右侧会显示运行轨迹。

## 创建与切换项目

左侧“创建项目”接收项目名称，“添加项目”会建立独立项目。点击项目列表可以切换当前范围。
对话、资料、记忆和检索均受当前项目约束。标题区显示当前项目名称和来源文档数量；数量不包括全部记忆节点。
左下角显示后端连接状态。当前产品采用单用户多项目模式，没有登录、成员管理和权限配置页面。

## 项目对话

“新建会话”建立当前项目下的会话。“当前会话”切换历史会话，浏览器记住每个项目最近选择的会话。
消息按顺序显示，较长历史可以向前加载。浏览器刷新后会重新加载消息和运行记录。

“模型”列出后端已配置的模型。前端不提供密钥输入框，也不直接请求模型厂商。
默认的 demo/evidence-demo 展示证据检索结果，不承担真实模型的推理能力。

“发送消息”启动一次智能体运行。运行时，右侧显示检索、模型调用和工具事件；回答完成后写入消息历史。
当前 SSE 传递过程事件和最终回答，尚未逐 token 显示模型输出。回答中的有效 si:// 引用可以打开来源检查器。

“允许智能体修改记忆”会为支持工具调用的模型开放提出候选、修改和忘记工具。
写工具执行前仍需在运行轨迹中审批；候选写入正式记忆还需进入记忆审核。
不勾选此选项不会关闭会话的后台记忆抽取，抽取产生的候选同样需要审核。

“立即抽取记忆”提前触发当前会话的增量抽取，供用户主动提交稳定事实。
该按钮不会直接接受候选；自然语言抽取需要后端配置生成模型，默认标记抽取模式只识别约定格式。

## 运行轨迹

“运行历史”可以切换当前会话的运行记录。轨迹面板显示状态、模型、迭代次数、模型报告的 token、
已预留 token 预算和追踪 ID。预留预算与模型报告的实际用量含义不同，页面不将预留量当作实际账单。

时间线记录运行开始、检索、模型调用、工具执行、记忆写入和结束等事件。
带持续时间的 span 表示受测操作；展开事件可以查看原始字段，原始 JSON 保留协议名称。
连接中断时，页面提示正在重连，并从持久化事件游标恢复记录。

待审批操作显示工具参数，用户可以批准或拒绝。完成后的操作可以展开结果。
“取消运行”请求后端停止尚未结束的运行，不表示已经执行的外部动作会自动撤销。
该页面读取 Si-agent 自己的持久化轨迹，不等同于嵌入 Langfuse 控制台。

## 上下文浏览

“导入资料”目前支持输入文档路径并粘贴 Markdown、文本或源代码，一次提交一份资料。
文档路径决定项目内的组织位置，不表示后端会读取本机同名文件。
当前没有文件拖拽上传、批量选文件、PDF 解析、网页抓取或整个 Git 仓库导入界面。

提交后，后台处理资料导入、分块、摘要表示和索引任务。页面显示导入任务状态、尝试次数及错误信息。
“上下文浏览”以缩进列表展示 si:// 目录、来源资料、会话和长期记忆；当前列表没有目录折叠操作。
点击节点会在页面下方打开检查器。“刷新”重新读取当前项目目录。

“检索项目证据”直接调用项目内检索，不调用模型生成回答，也不经过对话中的检索门。
该区域适合单独检查 RAG 召回和上下文组装，提供以下内容：

- 查询输入框和“包含来源详情（L2）”选项。
- 证据数量、上下文预算用量和混合检索或关键词检索提示。
- 每条命中的 URI、层级、片段与证据 ID，以及“打开来源”操作。
- 组装后的上下文、预算裁剪提示和原始检索阶段数据。
- 向量服务关闭、索引未就绪或演示向量等降级提示。

当前界面使用固定的 3000 单位上下文预算，没有检索参数设置面板。
是否具备语义检索能力取决于后端 Embedding 配置及索引就绪情况；哈希演示向量不提供语义能力。

## 记忆审核

候选列表显示新增、更新、替代和撤回等操作，以及待审核、已排队、已应用、已跳过和冲突等状态。
用户可以查看候选内容、修改前版本、预期版本和原始证据，再接受或跳过尚未处理的候选。
接受操作会排队执行合并，只有最终显示“已应用”才表示正式记忆已变更。
跳过操作保留原始来源，不会将该候选写成正式记忆。

右侧“待复核记忆”列出来源变化后暂不参与检索的记忆。当前页面提供检查入口，
没有一键自动消除语义冲突的操作。“后台记忆任务”展示最近 30 个任务的状态、尝试次数、错误和结果。

## 记忆检查器

检查器展示节点类型、si:// 地址、有效状态、正文版本与摘要表示版本。
用户可以在 L0 摘要、L1 概览、L2 详情之间切换；后台未启用模型摘要时，表示可能来自默认规则。
“来源证据”显示引用原文、版本和字符位置，并提供打开原始来源的按钮。
“版本对比”支持选择历史正文版本，与当前版本并排查看。

有效的事实、事件和流程记忆提供“修正这条记忆”。用户的新陈述会成为独立来源，
系统创建待审核 UPDATE，接受后才改变正式事实。新来源不会假借旧事实的证据支持新结论。

“撤回事实”使事实退出使用并保留历史；“忘记此来源”则脱敏正文、历史证据及已知派生项。
忘记前必须预览影响范围并勾选确认。忘记会话来源会同时脱敏对应用户消息；
忘记派生事实不会反向删除独立上游资料。忘记不能撤销已经发送给外部模型的请求。

## 推荐的首次体验

1. 创建测试项目，在上下文浏览中导入 `Decision[storage]: Use SQLite for the project database.`。
2. 在记忆审核中查看来源并接受候选，等待“已应用”。
3. 打开生成的记忆，提交 PostgreSQL/pgvector 的新陈述，再接受更新候选。
4. 在检查器中切换 L0/L1/L2，并展开版本对比和来源证据。
5. 新建会话询问 PostgreSQL，查看运行轨迹和回答引用；刷新页面检查恢复效果。
6. 在独立测试记忆上体验撤回或忘记，并观察审核、来源和版本的变化。

界面默认使用中文。模型标识、URI、用户资料及模型回复保持原文，原始调试 JSON 保留协议字段。
Eval Lab、Provider 配置编辑器、完整 Langfuse 服务联调和跨记忆后端质量对比属于后续工作。
